# Table tools and traffic

Progress clocks, party counters and rollable table definitions are bounded campaign state. They use the normal room patch and coalesced snapshot scheduler, with its existing concurrency and retry behavior. A campaign may hold 50 tools; a table has at most 50 entries of 200 characters and integer weights from 1 to 1000. Maximum-sized table definitions add under 600 KB to a snapshot in the regression test. Creating a tool or adjusting a value creates a room change; editing form drafts remain local. Players may adjust clocks and counters; only GMs may create, edit or delete tools. Table entries are only sent to GMs; players can roll by name and receive the result. Edits use a content digest to reject stale updates.

Presenting a handout sends a one-time, GM-authorized event containing the public fields, even if the handout is otherwise private. It does not change its library visibility or save a snapshot. Table results and map pings are also ephemeral and are not recovered after reconnect. Handout presentations and table results share an in-memory queue capped at 50; overflow produces a warning. A GM ping offers recipients a camera jump; it never forces a camera move and is ignored if its scene is no longer active. The server event regression test verifies that a handout presentation and table roll cause no additional saves.

Controls show local pending feedback for durable operations and report failures. The browser regression test measures first feedback for a clock adjustment in the local demo; it does not measure slower devices or network completion.
